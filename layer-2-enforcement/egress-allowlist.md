# Egress

Конфиг на ноутбуке разработчика — рекомендация: его можно удалить, забыть или переопределить. Enforcement — только сетевой уровень. Пока публичный реестр доступен напрямую, гейт остаётся договорённостью.

## Хосты, которые нужно закрыть

| Хост | Зачем закрывать |
|---|---|
| registry.npmjs.org | прямой доступ к npm мимо внутреннего реестра |
| registry.yarnpkg.com | второй npm-реестр, часто забывают (пункт 16) |
| pypi.org | прямой доступ к PyPI |
| files.pythonhosted.org | отдельный хост, с которого pip качает архивы; закрывать вместе с pypi.org (пункт 15) |
| repo.maven.apache.org | прямой Maven Central |
| codeload.github.com | tarball-зависимости (пункт 17) |
| objects.githubusercontent.com | объекты для git-зависимостей (пункт 17) |

Проверка после внесения правил:

```
curl -sS -o /dev/null -w '%{http_code}\n' https://registry.npmjs.org/express
npm view express --registry=https://registry.npmjs.org
```

Ожидаем: сетевой отказ или таймаут, а не 200. Повторите для каждого хоста таблицы.

## Чего закрытие не даёт

Docker Hub mirror не покрывает произвольные реестры: `FROM registry.example.com/team/image` обращается к другому хосту. `FROM` вообще обходит гейт зависимостей — это граница, описанная в ../BOUNDARIES.md. Для образов нужен отдельный контроль на уровне кластера.

Точно так же сетевой запрет не отменяет postinstall разрешённого пакета: пакет уже внутри, код выполняется локально. См. npm/README.md и ../BOUNDARIES.md.

## Исключения

Если часть хостов нужна для легатных целей, исключения делаются адресно и попадают в тот же процесс, что и break-glass: ../layer-3-catalog/break-glass-policy.md. Бессрочные исключения в сетевом правиле превращают enforcement обратно в рекомендацию.
